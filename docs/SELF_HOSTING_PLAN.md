# Self-Hosting Setup Script — Plan (Shop SW + G3ID)

Goal: another team forks this repo, runs `pnpm setup`, and gets **G3ID + Shop SW** deployed on
their own Cloudflare account and domain. Other apps (pit, scouting, skill-tree, attendance, web)
are out of scope for now. Branding is out of scope — this covers only what a working deployment needs.

---

## 0. Prerequisites (can't be scripted away)

| Requirement | Why |
|---|---|
| A domain with its DNS zone on Cloudflare | The G3ID session cookie is shared between `g3id.<domain>` and `shop.<domain>`. This can't work on `*.pages.dev` / `*.workers.dev` because they're public-suffix domains |
| Workers **Paid** plan ($5/mo) | Shop's `BOM_QUEUE` (OnShape ingest) uses Queues |
| Cloudflare API token | Workers, D1, KV, R2, Queues, Pages, Zone/DNS edit |
| Optional: Slack app, OnShape API keys + OAuth app, Google/GitHub/Steam OAuth apps | Features. **Email login and manual part entry work without any of them** |

---

## 1. Scope inventory

| Piece | Resources | Hostname |
|---|---|---|
| `g3id-production` worker | D1 `DB`, KV `SESSIONS`, KV `RATE_LIMIT` | `api.g3id.<domain>` |
| `shop-production` worker | D1 `SHOP_DB`, KV `SESSIONS` (**same namespace as g3id**), R2 `DRAWINGS`, Queue `bom-fetch-jobs`, service binding `G3ID` → `g3id-production` | `api.shop.<domain>` |
| `apps/g3id` (Pages) | — | `g3id.<domain>` |
| `apps/shop` (Pages, PWA) | — | `shop.<domain>` |

The service binding connects by **worker name**. As long as the names stay `g3id-production` / `shop-production`,
no IDs are needed for it. g3id must be deployed before shop.

## 2. Everything that must change

### 2a. `wrangler.toml`

| File | Account/domain-specific values |
|---|---|
| `workers/g3id/wrangler.toml` | prod D1 `database_id`; prod KV ids ×2; dev KV ids ×2 (these are real G3 IDs, so replace them with placeholders); `GOOGLE/GITHUB/STEAM/ONSHAPE_REDIRECT_URI`; `FRONTEND_URL`; team-owned `GOOGLE_CLIENT_ID`, `GITHUB_CLIENT_ID`, `ONSHAPE_CLIENT_ID`, `SLACK_TEAM_ID`, `SLACK_APP_ID`; **add** route `api.g3id.<domain>` (custom domain is currently set in the dashboard) |
| `workers/shop/wrangler.toml` | prod D1 id; prod + dev `SESSIONS` id; R2 `bucket_name` (`g3-bucket`); `FRONTEND_URL`; **add** route `api.shop.<domain>` |

Both `deploy` scripts currently run plain `wrangler deploy`, which deploys the **dev** config to
workers named `g3id`/`shop`. Change them to deploy production.

### 2b. Hardcoded domain in worker code

| Location | Effect on another domain |
|---|---|
| `workers/g3id/src/index.ts:30-33`, `workers/shop/src/index.ts:35-36` | CORS rejects every browser API call |
| `workers/g3id/src/lib/redirect.ts` | `?redirect=` dropped, so Shop's "log in" never returns to Shop |
| `workers/g3id/src/lib/cookie.ts` | Cookie domain = "last two labels", which is wrong for `.org.uk`, `.com.au`, etc. |
| `workers/g3id/src/routes/slack.ts:79` | Slack "return to browser" link goes to G3 |
| `workers/g3id/src/routes/admin.ts:73`, `workers/g3id/src/lib/slack-code.ts:164` | Links in Slack DMs |
| `workers/shop/src/lib/onshape-webhook.ts:129` | OnShape webhook registered to G3's API |
| `workers/shop/src/lib/bom-queue-consumer.ts:123,126` | Slack release-notification links |
| `workers/shop/src/routes/print.ts:11` | `shoppi-print.g3robotics.com` (G3's print server). Make it optional |

**Fix:** new worker vars `ROOT_DOMAIN`, `COOKIE_DOMAIN`, `API_URL` (g3id + shop), `SHOP_URL` (shop),
`PRINT_SERVER_URL` (optional; print route returns 404 if unset). CORS/redirect checks become
`host === ROOT_DOMAIN || host.endsWith("." + ROOT_DOMAIN)`.

### 2c. Hardcoded domain in frontend code

| Location | What |
|---|---|
| `apps/g3id/.env.production`, `apps/shop/.env.production` | API + G3ID URLs, generated by the script |
| `apps/shop/vite.config.ts:50-52` | PWA cache rule matches `api.shop.g3robotics.com`, so offline caching silently breaks. Read it from env |
| `apps/g3id/src/shared/nav-bar.tsx:83,136`, `apps/shop/src/shared/nav-bar.tsx:87,130` | "All Apps" → `web.g3robotics.com`. New optional `VITE_ALL_APPS_URL`; hide the link if unset |
| `apps/g3id/src/plugins/admin/admin-attendance-page.tsx` + links in `admin-kiosk-page.tsx:112`, `admin-users-page.tsx:321` | Attendance admin page. Hide the route and links when `VITE_ATTENDANCE_API_URL` is unset |
| `apps/g3id/vite.config.ts` `allowedHosts: [".grayjn.com"]` | Dev-only. Harmless, but should move to a local override |

### 2d. Cloudflare resources to create

D1 ×2 (auth, shop) · KV ×2 (sessions, rate-limit) · R2 ×1 (drawings) · Queue ×1 (`bom-fetch-jobs`) ·
Workers ×2 + custom domains · Pages ×2 + custom domains.

### 2e. Secrets

| Worker | Secret | Needed for |
|---|---|---|
| g3id | `SLACK_BOT_TOKEN`, `SLACK_SIGNING_SECRET` | Slack login |
| g3id | `GOOGLE_CLIENT_SECRET` / `GITHUB_CLIENT_SECRET` / `STEAM_API_KEY` / `ONSHAPE_CLIENT_SECRET` | each optional login provider |
| shop | `ONSHAPE_API_KEY`, `ONSHAPE_API_SECRET`, `ONSHAPE_COMPANY_ID`, `ONSHAPE_WEBHOOK_KEY_PRIMARY`, `ONSHAPE_WEBHOOK_KEY_SECONDARY` | OnShape ingest + drawings |
| shop | `SLACK_BOT_TOKEN`, `SLACK_SIGNING_SECRET` | release notifications (same Slack app as g3id) |
| shop | `PRINT_TOKEN` | print server (optional) |

**To verify during Phase 1:** each provider must fail gracefully (hidden button or clear error) when its
secret is unset, not throw a 500.

### 2f. Security: bootstrap admin

`workers/g3id/src/routes/auth/email.ts` creates an active admin **`admin@localhost` / `password`** on
the first email login attempt whenever no admin exists. On a fresh production deploy, anyone can
become admin. Fix:
- Only allow that bootstrap when `ENVIRONMENT=development`.
- The setup script seeds a real admin (prompted email + password, hashed with the worker's
  `hashPassword`, inserted via `wrangler d1 execute --remote`) **before** deploying g3id.

## 3. Design

### Config: `deploy/team.json` (committed; nothing in it is secret)

```jsonc
{
  "rootDomain": "g3robotics.com",
  "cookieDomain": "g3robotics.com",
  "resourcePrefix": "g3",
  "hosts": { "g3idApp": "g3id", "g3idApi": "api.g3id", "shopApp": "shop", "shopApi": "api.shop" },
  "optional": { "allAppsUrl": "https://web.g3robotics.com", "attendanceApiUrl": "", "printServerUrl": "" },
  "oauth": { "slackTeamId": "", "slackAppId": "", "googleClientId": "", "githubClientId": "", "onshapeClientId": "" },
  "cloudflare": {            // filled in by the script
    "accountId": "",
    "d1": { "auth": "", "shop": "" },
    "kv": { "sessions": "", "rateLimit": "" },
    "r2": { "drawings": "g3-drawings" },
    "queue": "bom-fetch-jobs"
  }
}
```

### Production wrangler config: template + render step

- `wrangler.toml` becomes **local-dev only**, with placeholder IDs and localhost URLs.
- Production is rendered from `wrangler.production.template.toml` + `team.json` into
  `wrangler.production.toml` (gitignored), then deployed with `--config`.
- Why not edit in place: every fork would conflict with upstream on those exact lines. With templates,
  upstream owns the template and each team owns only `team.json`.
- G3 should switch to this too, so the path teams use is the one that actually gets exercised.

### `pnpm setup` (`scripts/setup/index.ts`, run with `tsx`)

Every step looks for an existing resource by name before creating it, so re-running after a failure resumes cleanly.

1. **Preflight**: node/pnpm, `wrangler whoami` or `CLOUDFLARE_API_TOKEN`, zone exists for `rootDomain`,
   Queues available (Paid plan).
2. **Prompt**: domain, resource prefix, admin email/password, optional URLs. Saved to `team.json`.
3. **Provision**: D1 ×2, KV ×2, R2, Queue. IDs saved to `team.json`.
4. **Render**: both production wrangler configs + both apps' `.env.production`.
5. **Migrate**: `wrangler d1 migrations apply --remote` for auth + shop.
6. **Seed admin** (§2f).
7. **Secrets**: grouped by feature ("Enable Slack? OnShape? Google?"), pushed with `wrangler secret bulk`.
8. **Deploy workers**: g3id, then shop.
9. **Pages**: create Direct Upload projects `g3id` + `shop`, build, `wrangler pages deploy`,
   attach custom domains via the Cloudflare API.
10. **CI (optional)**: `gh secret set CLOUDFLARE_API_TOKEN CLOUDFLARE_ACCOUNT_ID`.
11. **Verify**: request each API + app URL and print a pass/fail table.
12. **Checklist**: print the exact URLs to paste into Slack / OnShape / OAuth consoles (§4).

Also add `pnpm deploy:shop` (render → migrate → deploy g3id + shop + both apps) for day-to-day use.

### CI: `.github/workflows/deploy.yml`

On push to `main`: install → render → migrate → deploy g3id worker → deploy shop worker →
build + `wrangler pages deploy` for both apps. Use path filters so a shop-only change doesn't
redeploy g3id. Because the Pages projects use Direct Upload, **nobody links GitHub in the Cloudflare
dashboard**. Also fix the pnpm version pin (CI uses 9; the workspace expects 10+).

## 4. Manual steps left (the script prints them with URLs filled in)

- **Slack app**: add `slack-app-manifest.template.yaml` to the repo (events URL
  `https://api.g3id.<domain>/slack/events`, `/signin` + `/link` commands at
  `https://api.g3id.<domain>/slack/commands/*`, bot scopes, `message.im` event). The script renders
  it, and the team pastes it into "Create app → From manifest".
- **OnShape**: create API keys; the OAuth app callback is `https://api.g3id.<domain>/auth/onshape/callback`.
  After deploy, the admin sets the document ID in Shop → Admin, which registers the webhook.
- **Google / GitHub / Steam** (optional): callback `https://api.g3id.<domain>/auth/<provider>/callback`.

## 5. Phases

| Phase | Work | Rough size |
|---|---|---|
| 1 | De-hardcode domains in g3id + shop (§2b, §2c); optional nav/attendance/print; gate bootstrap admin; check that providers fail gracefully | ~1 day |
| 2 | `team.json`, prod templates, render step, fix `deploy` scripts; move G3's own deploy onto it | ~½ day |
| 3 | `pnpm setup` script | 1–2 days |
| 4 | GitHub Actions deploy workflow; turn off dashboard Git integrations for g3id/shop | ~½ day |
| 5 | Slack manifest + "Deploy Shop SW for your team" README section | ~½ day |
| 6 | End-to-end run on a **fresh** Cloudflare account + throwaway domain | ~½ day |

Phase 1 is worth doing regardless: it fixes a real security issue (§2f) and removes hardcoded URLs.

## 6. Open decisions

1. **Queue optional?** Making `BOM_QUEUE` optional (skip OnShape ingest when it isn't bound) would let
   teams without OnShape run on the free plan.
2. **Fork vs. template repo**: fork recommended; merging upstream updates stays easy with §3 templates.
3. **Hostnames**: default to G3's layout (`shop.` / `api.shop.` / `g3id.` / `api.g3id.`), overridable in `team.json`.
4. **Later expansion**: the same pattern extends to pit/scouting/skill-tree/attendance, one worker
   template + a `team.json` entry each.
